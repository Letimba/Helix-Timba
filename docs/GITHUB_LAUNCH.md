# GitHub Launch Plan — HELIX

A 10,000-star week cannot be guaranteed. The repository should earn attention through a credible product, reproducible setup, transparent paper mode and useful engineering content.

## Launch checklist

- README opens with one-line value proposition and screenshot/GIF.
- Provide a 60-second demo showing Scanner → Strategy switch → Paper BUY → quote refresh → TP exit.
- Keep paper mode as the default and clearly label live execution as a separate future layer.
- Add issue templates, PR template, security policy and CI.
- Publish benchmark notes without claiming unsupported latency numbers.
- Tag releases and attach checksums.
- Add architecture diagrams and a short design rationale.
- Respond quickly to issues and pull requests.

## Metrics worth publishing

- startup time
- API response latency
- quote refresh success rate
- quote freshness
- strategy decision latency
- paper execution determinism
- test count and coverage

Do not publish fabricated trading returns or fabricated latency benchmarks.
